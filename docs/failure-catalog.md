# Failure catalog

Built from failures met while deploying SGLang on 4x RTX 4090 (PCIe) and 4x A100 (NVLink) machines. Signatures for the CUDA image, removed flags, NCCL, OOM, wedged-GPU and permission entries are the messages seen in the logs; disk-full, port-in-use and stalled-download signatures use the standard system messages. Generated by `llmeval catalog`; the catalog itself lives in `src/llmeval/doctor.py`.

## Container image needs a newer CUDA than the driver supports

- **id:** `cuda-image-newer-than-driver` (error)
- **signature:** `unsatisfied condition: cuda>=(\d+(?:\.\d+)?)`
- **cause:** The image was built for a newer CUDA runtime than the host driver can run (a `latest` tag moved to a CUDA 13 build while the driver supported up to CUDA 12.9).
- **fix:** Pin an image tag built for your driver's CUDA (see `CUDA Version` in nvidia-smi), or update the driver.

## SGLang no longer accepts --enable-prefix-caching

- **id:** `flag-removed-prefix-caching` (error)
- **signature:** `unrecognized arguments:.*--enable-prefix-caching`
- **cause:** Removed in newer SGLang (seen on 0.5.16, present on 0.5.10): the radix prefix cache is on by default.
- **fix:** Delete the flag from the launch command or compose file; prefix caching still works.

## SGLang no longer accepts --enable-expert-parallel

- **id:** `flag-renamed-expert-parallel` (error)
- **signature:** `unrecognized arguments:.*--enable-expert-parallel`
- **cause:** Replaced by an explicit size flag in newer SGLang (seen on 0.5.16).
- **fix:** Use `--ep-size N` (for example `--ep-size 4`).

## NCCL failed to initialise the multi-GPU communicator

- **id:** `nccl-init-failure` (error)
- **signature:** `NCCL error: unhandled system error|ncclCommInitRank`
- **cause:** Common in containers: too little shared memory, and unreliable peer-to-peer on PCIe consumer GPUs. Data-parallel replicas (one GPU each) never build a communicator, so they start fine.
- **fix:** Add `ipc: host` (or a large --shm-size); set NCCL_P2P_DISABLE=1 and NCCL_IB_DISABLE=1. Expect slower all-reduce / all-to-all; on NVLink machines leave P2P enabled.

## GPU out of memory while starting the server

- **id:** `gpu-oom-at-startup` (error)
- **signature:** `torch\.OutOfMemoryError|CUDA out of memory`
- **cause:** --mem-fraction-static too high once the engine's auxiliary processes are counted (0.85 overflowed 40 GB A100s; 80 GB cards did not).
- **fix:** Lower --mem-fraction-static (0.75 worked on 40 GB) and set PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True.

## A GPU became unusable (dead CUDA context)

- **id:** `gpu-wedged` (error)
- **signature:** `cudaErrorDevicesUnavailable`
- **cause:** Starting several servers at the same instant can race during CUDA initialisation and leave a dead context that a container cannot clear.
- **fix:** Start replicas about 15 s apart. If `nvidia-smi -r` reports Insufficient Permissions, stop/start the instance; if that fails, replace the machine.

## GPU reset is not permitted in this environment

- **id:** `gpu-reset-denied` (warning)
- **signature:** `Insufficient Permissions`
- **cause:** The container is not privileged, so the GPU cannot be reset from inside it.
- **fix:** Restart the instance from the provider's console, or move to a machine with privileged access.

## Listen port is already taken

- **id:** `port-in-use` (error)
- **signature:** `Address already in use|address already in use|port \d+ is already in use`
- **cause:** Another service (for example the provider's Jupyter on 8080) holds the port.
- **fix:** Pick another gateway port (8081 worked) and point clients at it.

## Disk is full (model cache)

- **id:** `disk-full` (error)
- **signature:** `No space left on device`
- **cause:** Several large checkpoints in one cache volume (a 32B bf16 model is about 64 GB; a 119 GB disk holds one or two).
- **fix:** Clear the Hugging Face cache between models, or use a bigger volume. Check `echo $HF_HOME` for the real cache path.

## Partial model download files present

- **id:** `download-incomplete` (warning)
- **signature:** `\.incomplete`
- **cause:** Two download processes wrote the same shards, or a download was interrupted and restarted repeatedly.
- **fix:** Kill duplicate downloaders, delete the `.incomplete` shards, then download once.

## Multimem all-gather unavailable (benign)

- **id:** `multimem-allgather-disabled` (info)
- **signature:** `multimem all-gather disabled`
- **cause:** The GPUs do not support NVLink multimem; the engine falls back to a normal all-gather.
- **fix:** No action needed.
